# Quick Task 260428-n51: Fix canvas aspect ratio and prevent duplicate publish

## What was done

### Bug 1: Fragment aspect ratio distorted on canvas

**Root cause:** `handleFragmentUploaded` only spread `localData.src` onto the new canvas fragment — not `width`, `height`, `originalWidth`, `originalHeight`. These fell back to `toCanvasFragment` defaults (240×240 square), squashing non-square images. For already-saved fragments loaded from the DB, the same defaults applied if metadata was missing.

**Fix:**
- `handleFragmentUploaded`: now spreads actual `localData` dimensions (computed proportionally at MAX 320px by the background-removal hook).
- `FragmentNode.useEffect`: on image load, computes correct display dimensions from `image.naturalWidth/Height` and calls `onUpdate` to sync state for future saves. Also derives `displayW/displayH` from the loaded image for immediate correct rendering — no more relying on stored fragment dims.

### Bug 2: Users could publish multiple attempts

**Root cause:** `GET /api/projects/:id/attempts/me` only queried `status = 'draft'`. After publishing, this returned 404, so the client never set `isPublished=true`, and the Publish button reappeared on page reload. Additionally, `POST /api/projects/:id/attempts` could create a new draft even after the user's attempt was published, enabling a second publish.

**Fix:**
- Server `GET /attempts/me`: now returns the user's most recent attempt of any status. Client's existing `if (draft.status === 'published' || draft.status === 'approved') setIsPublished(true)` now fires correctly.
- Server `POST /attempts` upsert: blocks new draft creation if user already has a `published` or `approved` attempt (returns 409).
- Client Save Attempt button: `disabled={saving || isPublished}` — locked after publish so state is consistent.
