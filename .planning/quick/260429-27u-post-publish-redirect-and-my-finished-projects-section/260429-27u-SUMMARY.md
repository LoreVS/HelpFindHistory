# Phase quick Plan 260429-27u: Post-Publish Redirect and My Finished Projects Section Summary

**One-liner:** Post-publish redirect to /projects and a second card grid showing each user's published/approved/rejected attempts with attempt status pills.

## What Was Built

### Task 1 — Server endpoint + store action
- `GET /api/attempts/me` route added to `server/routes/attempts.js`. Uses `requireAuth` (already applied at router level). SQL JOINs `attempts` to `projects` on `project_id`, filters `status IN ('published','approved','rejected')`, orders by `submitted_at DESC`. Returns empty array when user has no finished attempts (never 404).
- `myAttempts: []` state slice added to `useProjectStore` initial state.
- `fetchMyAttempts()` action added using the same `authHeaders()/fetch` pattern as `fetchProjects()`. On error, logs to console and sets `myAttempts: []` without touching `error` state.

### Task 2 — UI changes
- `ProjectDetailPage.handlePublishAttempt`: replaced `setSaveMsg('Attempt published.')` + `setTimeout` with `navigate('/projects')` immediately after `setIsPublished(true)`.
- `ProjectsPage`: destructures `myAttempts` + `fetchMyAttempts` from store; `useEffect` now calls `fetchMyAttempts()` alongside `fetchProjects()` for non-admin users; `attemptStatusLabel()` helper maps `'published'` to `'on review'` and passes `'approved'`/`'rejected'` through unchanged.
- My Finished Projects section rendered below the main grid when `role !== 'admin' && myAttempts.length > 0`: uses existing `project-card` and `card-status` classes for consistency, adds `attempt-pill` with per-status color variants.
- `ProjectsPage.css`: added `.finished-section`, `.finished-title`, `.attempt-pill`, `.attempt-pill--published`, `.attempt-pill--approved`, `.attempt-pill--rejected`.
