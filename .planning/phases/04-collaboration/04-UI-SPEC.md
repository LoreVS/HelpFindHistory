## Spacing Scale

Declared values used in this codebase (4px-multiple grid):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status badge internal padding (vertical) |
| sm | 8px | Canvas toolbar vertical padding, table cell padding, toolbar action button gap |
| md | 16px | Button horizontal padding, toolbar gaps |
| lg | 20px | Page header padding (horizontal) |
| xl | 28px | Modal padding, attempts section padding |
| 2xl | 40px | Bottom scroll clearance in attempts section |

Exceptions:
- `8px` gap between toolbar action buttons (Phase 4 target; pre-existing Phase 3 CSS `.canvas-toolbar-actions { gap: 10px }` is locked to its existing class and must not be changed)
- `8px` gap inside form groups (Phase 4 target; pre-existing Phase 3 CSS `.form-group { gap: 6px }` is locked to its existing class and must not be changed)
- `16px` gap between modal stack items (matches existing `.attempt-modal { gap: 16px }`)

> Note: Pre-existing Phase 3 classes (`.canvas-toolbar-actions`, `.form-group`) retain their current values. The 8px values above apply only to Phase 4 new CSS classes.

## Typography

All text uses `'Courier New', monospace`. This contract covers Phase 4 new additions only.
No size or weight outside the four tiers below may be introduced in Phase 4 CSS.

| Role | Size | Weight | Line Height | Letter Spacing | Transform |
|------|------|--------|-------------|----------------|-----------|
| Label / badge / feedback / read-only toolbar / btn text | 0.78rem (~12.5px) | 400 | — | 0.08–0.1em | uppercase where noted |
| Secondary body / dialog body | 0.83rem (~13.3px) | 400 | 1.5 | — | — |
| Primary body / table cell | 0.9rem (~14.4px) | 400 | 1.5 | — | — |
| Page / detail title (h1) | 1rem (~16px) | 700 | — | 0.1em | — |

Mapping from pre-existing sizes:
- `0.8rem` buttons → mapped to `0.78rem` in Phase 4 new classes (`.btn-save-attempt`, `.btn-publish-attempt`, `.btn-publish-confirm`)
- `0.88rem` h2 → mapped to `0.83rem` in Phase 4 new classes

> Note: Sizes `0.7rem` and `0.88rem` exist in pre-existing Phase 3 CSS; they are outside Phase 4 contract scope and must not be changed.

Source: measured from existing CSS — no new sizes introduced beyond the four tiers above.

## New Phase 4 UI Elements

This section is the primary addition to the design contract. Each element maps to
a new CSS class that must be added to `ProjectDetailPage.css`.

### 1. User canvas toolbar (role !== 'admin', project open)

The existing `.canvas-toolbar` is reused. When `role !== 'admin'` and the project
is open, the toolbar renders:

- Left: `.canvas-toolbar-title` — unchanged label text (see Copywriting below)
- Right: `.canvas-toolbar-actions` flex row containing, in order:
  1. `.attempt-msg` (conditional) — feedback message
  2. `.btn-save-attempt` — Save Attempt button
  3. `.btn-publish-attempt` — Publish Attempt button (hidden/disabled once published)

```css
/* Matches .btn-save-layout exactly — amber outline, fills on hover */
.btn-save-attempt {
  background: transparent;
  border: 1px solid #e8b84b;
  color: #e8b84b;
  padding: 4px 16px;
  font-family: 'Courier New', monospace;
  font-size: 0.78rem;
  letter-spacing: 0.08em;
  cursor: pointer;
  transition: background 0.15s, color 0.15s;
}
.btn-save-attempt:hover:not(:disabled) { background: #e8b84b; color: #111; }
.btn-save-attempt:disabled { opacity: 0.4; cursor: not-allowed; }
```

### 2. Publish Attempt button

Visually distinct from Save Attempt via label only — same amber outline pattern.
Once the attempt is published (status === 'published' or 'approved'), this button
is removed from the DOM entirely (not just disabled), per D-11.

```css
/* Identical token values to .btn-save-attempt — same class family */
.btn-publish-attempt {
  background: transparent;
  border: 1px solid #e8b84b;
  color: #e8b84b;
  padding: 4px 16px;
  font-family: 'Courier New', monospace;
  font-size: 0.78rem;
  letter-spacing: 0.08em;
  cursor: pointer;
  transition: background 0.15s, color 0.15s;
}
.btn-publish-attempt:hover:not(:disabled) { background: #e8b84b; color: #111; }
.btn-publish-attempt:disabled { opacity: 0.4; cursor: not-allowed; }
```

### 3. Attempt feedback message

Matches existing `.save-msg` pattern exactly. Reuse `.save-msg` class — no new
class needed. Success text is `#5ccc5c`; error falls back to `.detail-error` color
`#e05c5c` by adding the modifier class `.save-msg--error`.

```css
.save-msg--error {
  color: #e05c5c;
}
```

The `.attempt-msg` alias is acceptable but `.save-msg` is preferred for
consistency with admin Save Layout feedback.

### 4. Publish confirmation dialog

Displayed when the user clicks "Publish Attempt". Rendered as a centered modal
overlay. Reuses the existing `.attempt-modal-backdrop` and `.attempt-modal`
classes. No new modal classes are needed.

Layout inside `.attempt-modal`:
1. `<h3>` — dialog title
2. `<p className="attempt-modal-placeholder">` — warning body (non-italic — override font-style)
3. `.attempt-modal-actions` flex row — Publish now button + Keep editing button

```css
/* Override italic style from existing .attempt-modal-placeholder for warning copy */
.publish-confirm-body {
  color: #d4c5a9;
  font-size: 0.83rem;
  font-style: normal;
  line-height: 1.5;
  margin: 0;
}
```

Publish now button — solid amber fill (permanent action severity, not destructive):

```css
.btn-publish-confirm {
  background: #e8b84b;
  color: #111111;
  border: none;
  padding: 8px 16px;
  font-family: 'Courier New', monospace;
  font-size: 0.78rem;
  font-weight: 700;
  letter-spacing: 0.06em;
  cursor: pointer;
  transition: opacity 0.15s;
}
.btn-publish-confirm:hover { opacity: 0.88; }
```

Keep editing button — reuse `.btn-modal-close` (transparent, `#333` border, `#888` text).
No new class needed.

### 5. Draft attempt status badge

New badge variant for attempts with status `draft`. Reuses the `.attempt-status`
base class with a new modifier.

```css
.attempt-status--draft {
  background: #1a1a2a;
  color: #888;
  border: 1px solid #2a2a4a;
}
```

### 6. Read-only canvas (closed project view, D-15, D-18)

When `isClosed === true` and `role !== 'admin'`, the canvas toolbar shows a
read-only label instead of action buttons. No new wrapper class is needed — the
`.canvas-toolbar-title` already exists. A `.canvas-toolbar-readonly` modifier
adjusts its color to signal non-interactivity:

```css
.canvas-toolbar-readonly {
  font-size: 0.78rem;
  letter-spacing: 0.08em;
  color: #555;
  text-transform: uppercase;
  font-style: normal;
}
```

The Konva `Transformer` node is NOT rendered for closed canvas. Fragment `Group`
nodes have `draggable={false}` and no `onDragEnd`/`onTransformEnd` handlers.
No CSS class required — controlled via React props.

### 7. Solver attribution (D-17)

Displayed immediately below the canvas wrap (inside `.detail-canvas-area`), above
the horizontal border that separates canvas from attempts section.

```css
.canvas-solver {
  padding: 8px 16px;
  font-size: 0.78rem;
  color: #888;
  letter-spacing: 0.06em;
  border-top: 1px solid #222;
  background: #141414;
  flex-shrink: 0;
}

.canvas-solver-email {
  color: #d4c5a9;
  font-weight: 400;
}
```

Rendered markup:

```jsx
<div className="canvas-solver">
  SOLVED BY: <span className="canvas-solver-email">{solution.submitter_email}</span>
</div>
```

This element is only rendered when `isClosed === true` and `solution` is present
in the project data.

## State Loading Order

When a user opens `/projects/:id`:

1. `fetchProject(id)` called — loads project + fragments + approved attempt (if closed).
2. If `role !== 'admin'` and project is open:
   - Call `fetchUserDraft(projectId)` from `useProjectStore`.
   - If draft exists: hydrate `canvasFragments` from draft's `layout` JSON.
   - If no draft: hydrate `canvasFragments` from admin's fragment `metadata` (reference layout), per D-04 and D-12.
3. If project is closed:
   - Hydrate `canvasFragments` from `project.solution.layout` JSON, per D-16.
   - Render solver attribution from `project.solution.submitter_email`, per D-17.
