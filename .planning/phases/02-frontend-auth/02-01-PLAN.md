  <behavior>
    - useAuthStore.getState().token is null initially
    - After login(token, user), useAuthStore.getState().token === token and .user === user
    - After logout(), token and user are both null
    - init() with a token whose exp < now (seconds) clears token and user to null
    - init() with a valid (non-expired) token leaves token and user unchanged
    - init() with a malformed token (not a valid JWT) clears token and user to null
    - Zustand persist writes to localStorage key 'auth-storage'
    - initialized flag is false before init() is called, true after
  </behavior>
  <action>
    Create `/Users/apple/Desktop/Vortex/puzzle-fragments/src/store/authStore.js` with the following exact implementation:

    ```js
    import { create } from 'zustand'
    import { persist } from 'zustand/middleware'

    const useAuthStore = create(
      persist(
        (set, get) => ({
          user: null,
          token: null,
          initialized: false,

          login(token, user) {
            set({ token, user })
          },

          logout() {
            set({ token: null, user: null })
          },

          init() {
            const { token } = get()
            if (!token) {
              set({ initialized: true })
              return
            }
            try {
              const payload = JSON.parse(atob(token.split('.')[1]))
              if (payload.exp * 1000 < Date.now()) {
                set({ token: null, user: null, initialized: true })
              } else {
                set({ initialized: true })
              }
            } catch {
              set({ token: null, user: null, initialized: true })
            }
          },
        }),
        {
          name: 'auth-storage',
          partialize: (state) => ({ token: state.token, user: state.user }),
        }
      )
    )

    export default useAuthStore
    ```

    Key decisions per D-05, D-06, D-07:
    - `persist` middleware from `zustand/middleware` — partialize persists only token + user (not initialized)
    - `name: 'auth-storage'` is the localStorage key
    - `init()` decodes JWT `exp` claim via `atob(token.split('.')[1])` — no external library needed
    - `exp` is in seconds, `Date.now()` is in milliseconds → multiply exp by 1000 to compare
    - `initialized` is set to true after init() regardless of outcome — used by App to render null during boot
    - `initialized` is NOT persisted (not in partialize) — always starts false, becomes true after init() call
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → authStore | Token read from localStorage on app boot; malicious data could be stored there |
| JWT client-side decode | atob() decode of JWT payload — untrusted data from localStorage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | authStore init() | mitigate | atob decode wrapped in try/catch — malformed or tampered token silently clears store and sends user to /login (no crash, no bypass) |
| T-02-02 | Elevation of Privilege | useRole() / localStorage | accept | Client-side role is display-only (badge visibility). Server enforces RBAC via requireRole middleware on every protected API call. Spoofing role in localStorage shows an ADMIN badge but grants zero server access. |
| T-02-03 | Spoofing | authStore token | accept | Token is opaque string from server; client never constructs tokens. ProtectedRoute checks token presence only; server verifies signature + denylist on every API request. |
| T-02-04 | Information Disclosure | localStorage 'auth-storage' | accept | localStorage is same-origin only. No PII beyond email + role stored. Token expiry enforced by init(). Deferred: httpOnly cookie upgrade post-v1.1 (noted in CONTEXT.md deferred section). |
</threat_model>
