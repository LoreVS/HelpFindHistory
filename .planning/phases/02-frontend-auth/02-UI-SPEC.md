## Page Specs

### /login — Login Page

**Layout:** Full-page centered column. `#0f0f0f` body. A single vertically-centered card (max-width 400px, background `#c6e4eb`, border `1px solid #2a2a2a`, border-radius 10px, padding `32px`).

**Header block (inside card):**
- `PUZZLE FORGE` in Bebas Neue 28px `#e8b84b`, letter-spacing 0.12em
- Tagline `// відновлення форми з уламків` in IBM Plex Sans 14px `#555` below the logo
- Page heading `ACCESS TERMINAL` in JetBrains Mono 20px weight 500 `#dedad3`, margin-top 24px

**Form fields (stacked, gap 16px):**
1. Email input — label "email" (IBM Plex Sans 14px `#555`), input below (IBM Plex Sans 14px, background `#151d65`, border `1px solid #2a2a2a`, border-radius 6px, padding `8px 16px`, color `#dedad3`)
2. Password input — label "password", same styling as email input

**CTA button:** Full-width. Text `AUTHENTICATE` in Bebas Neue 16px weight 500, background `#e8b84b`, color `#0f0f0f`, border none, border-radius 6px, height 44px, letter-spacing 0.08em. Hover: `background: rgba(232,184,75,0.85)`. Disabled (loading): `opacity: 0.5`, cursor `not-allowed`.

**Navigation link:** `Don't have an account? Register →` — IBM Plex Sans 14px, color `#555`, centered below button, margin-top 16px. "Register →" portion in `#e8b84b` on hover.

**Error state:** A red banner `background: rgba(224,82,82,0.12); border: 1px solid #e05252; border-radius 6px; padding: 8px 16px` above the submit button. Text in IBM Plex Sans 14px `#e05252`.

**Focus states:** Input focus border-color `#e8b84b`, outline none.

**Page heading:** `CREATE ACCOUNT` in JetBrains Mono 20px weight 500 `#dedad3`.

**Form fields (stacked, gap 16px):**
1. Email input — label "email"

**Error state:** Same red banner pattern as /login (`padding: 8px 16px`). Appears above the CTA button.

**Password mismatch validation (client-side):** Show error banner with copy "passwords do not match" before form submission if confirm password differs. Do not call API.

---

### Header Badge (Admin)

**Where:** In the existing `.header` flex row, inserted between the tagline `<span>` and the `.header-hint` div. Aligned left-of-center, immediately after the tagline.

**Appearance:** A small pill/badge. Background `rgba(232,184,75,0.15)`, border `1px solid rgba(232,184,75,0.4)`, border-radius 4px, padding `4px 8px`. Text `ADMIN` in JetBrains Mono 14px weight 500 `#e8b84b`, letter-spacing 0.08em.

**Visibility:** Rendered only when `useRole()` returns `'admin'`. When user is `'user'` or unauthenticated, element is not present in DOM (not hidden via CSS — conditional render in JSX).

**END SESSION control:** A `END SESSION` text button appears at the far right of the header (right side of the `.header-hint` area) when a user is authenticated. JetBrains Mono 14px `#555`, hover color `#e05252`. Clicking invokes `authStore.logout()` and redirects to `/login`.

## Component Contracts

### LoginForm

**Fields:**
- `email` — type `email`, required, no placeholder (label floats above)
- `password` — type `password`, required

**Validation:**
- Client-side: Both fields must be non-empty. Show "email and password are required" if either is blank on submit attempt.
- Server-side: Display API error message verbatim in the error banner.

**Loading state:** On submit, disable all inputs + button, set button text to `AUTHENTICATING…` (Bebas Neue). No spinner — text change only.

**Error display:** Error banner above CTA button. Disappears when user starts typing in any field.

**Success:** Call `authStore.login(token, user)`, then `navigate('/')`.

---

### RegisterForm

**Fields:**
- `email` — type `email`, required
- `password` — type `password`, required, minimum 8 characters (client-side hint only — server enforces)
- `confirmPassword` — type `password`, required

**Validation:**
- Client-side: All fields non-empty. Passwords must match before API call. Show "passwords do not match" if they differ.
- Server-side: Display API error verbatim in error banner.

**Loading state:** On submit, disable all inputs + button, set button text to `REGISTERING…`. No spinner.

**Error display:** Error banner above CTA button. Disappears on any field change.

**Success:** Per D-10 — API returns token + user; call `authStore.login(token, user)`, then `navigate('/')` (auto-login, no separate login step).

---

### ProtectedRoute

**No visual output.** Pure routing logic component.

**Behavior:**
1. Read `token` from `authStore`.
2. If token is absent or expired (checked via `authStore.init()` on app boot) → `<Navigate to="/login" replace />`.
3. If token is valid → render `<Outlet />` (or children).

**Auth init on app boot:** `useEffect(() => authStore.init(), [])` in the root `App` component — runs once, validates JWT `exp` claim, clears expired token and redirects. No loading flash: use a simple `initialized` boolean in authStore. While `!initialized`, render `null` (blank screen, ~0ms for localStorage read).

---

### useRole()

**Signature:** `useRole() → string | null`

**Returns:** `authStore.user?.role` — one of `'admin'`, `'user'`, or `null` (unauthenticated).

**No visual output.** Pure hook consumed by header badge and future phase components.

## Interaction Contracts

| Interaction | Behavior |
|-------------|----------|
| Form submit — loading | Disable all inputs and CTA. Change button text to loading copy. No spinner. |
| Auth success (login) | `authStore.login(token, user)` → `navigate('/')` immediately. |
| Auth success (register) | Same as login success — auto-login per D-10, no manual login step. |
| Auth failure | Re-enable form. Populate error banner above CTA. Clear banner on next keystroke. |
| Token expired on reload | `authStore.init()` detects `exp < now` → clears store + localStorage → `navigate('/login')` (via ProtectedRoute redirect, not imperative navigate). |
| Valid token on reload | `authStore.init()` rehydrates user + token → protected route renders normally. |
| END SESSION | `authStore.logout()` (clears store + localStorage) → `navigate('/login')`. Per D-11. |
| END SESSION confirmation | none — immediate logout by design |
| Navigate to protected route while logged out | `ProtectedRoute` fires `<Navigate to="/login" replace />` before any content renders. |
| Navigate to /login or /register while logged in | Redirect to `/` (add a `PublicOnlyRoute` wrapper that mirrors ProtectedRoute logic in reverse). |
| Admin badge | Renders in header DOM only when `useRole() === 'admin'`. No transition — instant conditional render. |
