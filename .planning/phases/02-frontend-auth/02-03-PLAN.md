    ```jsx
    import { StrictMode } from 'react'
    import { createRoot } from 'react-dom/client'
    import { BrowserRouter } from 'react-router-dom'
    import './index.css'
    import App from './App.jsx'
    import useAuthStore from './store/authStore.js'

    // D-07: Validate JWT expiry on app boot before React renders.
    // init() reads localStorage (synchronous via Zustand persist rehydration),
    // decodes the exp claim, and clears expired tokens. Sets initialized=true.
    useAuthStore.getState().init()

    createRoot(document.getElementById('root')).render(
      <StrictMode>
        <BrowserRouter>
          <App />
        </BrowserRouter>
      </StrictMode>,
    )
    ```

    Key decisions implemented:
    - D-01: BrowserRouter wraps App (react-router-dom v7 data router approach uses createBrowserRouter, but BrowserRouter is simpler and correct here since we define Routes inside App.jsx)
    - D-07: `useAuthStore.getState().init()` called BEFORE `createRoot().render()` — imperative store call, not inside a React component. This ensures the store is initialized before any component reads it. The `initialized` flag is set to true synchronously inside init().
    - StrictMode stays outermost (wraps BrowserRouter + App)
    - `./store/authStore.js` import uses the .js extension explicitly (consistent with existing main.jsx pattern for App.jsx)

    Note on the init() call placement: It runs synchronously before React renders any component. Zustand persist rehydrates localStorage synchronously when the store module is first imported (this is how Zustand persist works — the rehydration happens on module import). By the time init() is called, the token is already in the store from localStorage. init() then validates the exp claim and sets initialized=true. When React renders, initialized is already true, so ProtectedRoute never renders null in normal operation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser URL → React Router | User can manually type any URL; route guards enforce auth checks |
| localStorage rehydration → authStore | Token loaded from localStorage before React renders |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Spoofing | ProtectedRoute / BrowserRouter | mitigate | ProtectedRoute checks token presence on every render. Direct URL navigation to / while logged out is caught and redirected to /login before any canvas content renders. |
| T-02-11 | Tampering | main.jsx init() call | mitigate | init() called before React renders — expired token is cleared before ProtectedRoute ever reads it. Race condition between init() and route render is eliminated. |
| T-02-12 | Elevation of Privilege | Admin badge in header (ROLE-03) | accept | Badge is display-only. No admin controls exist in Phase 2. Server RBAC (requireRole) is the enforcement mechanism. Spoofing role in localStorage shows badge but grants zero server access. |
| T-02-13 | Denial of Service | END SESSION button | accept | No confirmation dialog by design (UI-SPEC: "none — immediate logout"). Accidental click is low-risk in local dev context. |
| T-02-14 | Information Disclosure | PublicOnlyRoute redirect | accept | Redirecting logged-in users from /login → / does not expose sensitive info. The redirect reveals only that the user is logged in, which they already know. |
</threat_model>
