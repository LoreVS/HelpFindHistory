# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5: Scoring (Puzzle Forge).
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

> form, (2) attempt review modal with live Konva canvas preview, (3) approve

## Color

All tokens inherited. Phase 5 introduces one new usage context for the green semantic cluster.

| Role | Value | Phase 5 Usage |
|------|-------|---------------|
| Dominant (60%) | `#111111` | Confirm Approve button text; canvas preview background |
| Secondary surface | `#1a1a1a` | Confirm modal background |
| Text primary | `#d4c5a9` | Confirm modal h3, body copy |
| Text secondary | `#888` | Score chip text (neutral variant — see note below) |
| Border primary | `#2a2a2a` | Canvas preview container border; score chip border (neutral variant) |
| Surface dim | `#161616` | Score chip background (neutral variant) |
| Accent (amber) | `#e8b84b` | NOT used for score chip (reserved for admin/action elements) |
| Approve semantic (bg/text/border) | `#1a3a1a` / `#5ccc5c` / `#2d6b2d` | Confirm Approve button fill; score chip positive variant |
| Destructive | `#cc4444` | NOT used in Phase 5 (reject is non-destructive, no confirm needed) |
| Reject text | `#cc5555` | Reject button text (pre-existing, `.btn-reject`) |

**Score chip color decision (Claude's discretion, D-11):**
Use the neutral variant: background `#161616`, color `#888`, border `#2a2a2a`. Rationale: the green semantic cluster is already occupied by approved/open-project status signals. A neutral chip avoids false positive connotation (a score of 0 should not look "approved"). The star glyph alone conveys earned status.

**Accent (`#e8b84b`) reserved for** (Phase 5 additions to the existing list):
- No new additions. The reward input uses the existing `.form-group input:focus` amber border — no new reservation needed.

**Destructive (`#cc4444`) reserved for:**
- No new additions. Reject action is immediate-close with no confirm (D-08) — the existing `btn-reject` styling (muted red outline) suffices.

## New Phase 5 UI Elements

### 1. Reward number input (ProjectsPage.jsx New Project form)

Added as a new `.form-group` block below the existing Description field. Reuses all existing `.form-group`, `label`, and `input` styles with no new CSS needed. The `.form-group input` already handles number inputs correctly.

**Markup pattern:**
```jsx
<div className="form-group">
  <label htmlFor="reward">Reward (pts)</label>
  <input
    id="reward"
    type="number"
    min="1"
    value={reward}
    onChange={e => setReward(e.target.value)}
    placeholder="e.g. 5"
  />
</div>
```

No new CSS class. Existing `.form-group` handles layout. Existing `.form-group input:focus` handles amber focus ring.

---

### 2. Attempt review modal — canvas preview modifier

The existing `.attempt-modal` is reused. A width-modifier class `.attempt-modal--canvas` overrides `max-width` to accommodate the Konva canvas.

The canvas preview container `.attempt-modal-canvas` sits between the attempt metadata header and the approve/reject action row.

```css
/* Add to ProjectDetailPage.css */

/* Wider modal to fit canvas preview */
.attempt-modal--canvas {
  max-width: 720px;
  width: 100%;
}

/* Canvas preview area inside the review modal */
.attempt-modal-canvas {
  width: 100%;
  height: 340px;
  background: #111111;
  border: 1px solid #222222;
  overflow: hidden;
  display: flex;
  align-items: center;
  justify-content: center;
  flex-shrink: 0;
}
```

The Konva `Stage` renders inside `.attempt-modal-canvas` with `draggable={false}`, no `Transformer`, and no drag/transform event handlers. Reuses the `readOnly` prop pattern from `ProjectCanvas` (established in COLLAB-05).

Canvas dimensions inside modal: `width: 680` / `height: 340` (Konva Stage pixels). These match the container dimensions minus the 1px border on each side. Fragment images loaded from `server/data/uploads/{projectId}/` via their `src` path; positioned using the attempt's `layout` JSON (same `toCanvasFragment()` helper).

### 4. Score chip in site header (SCORE-05)

Displayed for `role === 'user'` only. Placed inside `.projects-header-right` and `.detail-header-right` immediately before the `.btn-end-session` button.

Added to `App.css` alongside `.admin-badge` (same file, same section).

```css
/* Add to App.css, in the "Admin badge" section */

.score-chip {
  background: #161616;
  border: 1px solid #2a2a2a;
  border-radius: 4px;
  padding: 4px 8px;
  font-family: 'JetBrains Mono', monospace;
  font-size: 14px;
  font-weight: 400;
  color: #888;
  letter-spacing: 0.06em;
  line-height: 1;
  flex-shrink: 0;
}
```

Rendered markup (JSX, role-gated):
```jsx
{role === 'user' && (
  <span className="score-chip">&#9733; {score}</span>
)}
```

The `&#9733;` HTML entity is the filled star glyph (★). No external icon library needed.

Score value sourced from `GET /api/users/me` on app boot (D-12, Claude's discretion). The `score` field is stored in component or auth store state. Score is re-fetched after an attempt is approved to ensure freshness.

## State Loading Order

When admin opens the attempt review modal:
1. Modal mounts with `attempt.layout` already available in the project data (returned by `GET /api/projects/:id` — D-06, no new fetch needed).
2. `ProjectCanvas` renders with `readOnly={true}`, `fragments` hydrated from `toCanvasFragment()` applied to the attempt's `layout` entries.
3. Approve / Reject buttons active once canvas has mounted.

When admin confirms approval:
1. `POST /api/attempts/:id/approve` fires (db.transaction: 4 writes — D-13).
2. Confirm modal shows "Approving…" state on button, both buttons disabled.
3. On success: both modals close, `fetchProject()` re-called to refresh project status + attempt list.
4. Score chip in header re-fetches `GET /api/users/me` for the now-awarded user (reflected on their next page view — no real-time push in v1.1).

When user loads any page (ProjectsPage or ProjectDetailPage):
1. `GET /api/users/me` called on auth init (alongside existing token validation).
2. `score` stored in auth store or local component state.
3. Score chip renders immediately with fetched value; shows `★ …` during initial fetch.
